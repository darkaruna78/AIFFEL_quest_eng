# [POC] FINCX 라이팅 최적화 멀티 에이전트 시스템

이 파일은 금융권 CX 라이팅 최적화 에이전트(Multi-agent) 시스템을 구축하고 테스트하기 위한 입력 예시 및 설계 명세서입니다.

---

## 1. 프로젝트 개요
- **목표**: 금융사의 브랜드 톤앤매너를 준수하고, 법률적 리스크(컴플라이언스)를 자동으로 검수하며, 어려운 용어를 순화하는 멀티 에이전트 기반 라이팅 보조 툴 구축
- **기간**: 4일 (POC 단계)
- **핵심 아키텍처**: CrewAI를 활용한 4단계 순차적 체인(Sequential Chain)

---

## 입력 방법 1: 간단한 비즈니스 요구사항

```text
금융사 CX 라이팅 최적화 시스템 설계:

에이전트 구성:
1. Glossary_Agent: 어려운 금융 용어를 '순화어 DB(JSON)' 기반으로 쉬운 우리말로 변경
2. Stylist_Agent: '브랜드 가이드(Prompt)'에 따라 말투를 다정하고 신뢰감 있게 수정
3. Auditor_Agent: '컴플라이언스 가이드'를 참조하여 금지어 및 법적 필수 문구 검수
4. Editor_Agent: 최종 결과물 취합 및 각 단계별 수정 근거(Reasoning) 요약

관계 및 흐름:
- 입력 문구 -> Glossary -> Stylist -> Auditor -> Editor -> 최종 출력
- Auditor에서 부적합 판정 시 Stylist 단계로 다시 피드백(Loopback)
```

---

## 입력 방법 2: 브랜드 가이드 및 지식베이스 (JSON)

에이전트가 참조할 마스터 지식베이스 예시입니다.

```json
{
  "brand_voice": {
    "persona": "든든한 자산관리 전문가",
    "tone": "다정한, 전문적인, 명확한",
    "suffix": "~해요, ~할게요 (해요체 권장)",
    "rules": ["기술 용어 지양", "고객 중심의 능동태 사용"]
  },
  "glossary_db": [
    { "bad": "부결/거절", "good": "승인이 어려워요", "reason": "거부감 완화" },
    { "bad": "내점", "good": "방문", "reason": "한자어 순화" },
    { "bad": "거치식", "good": "목돈을 한꺼번에 맡기는", "reason": "개념 풀이" }
  ],
  "compliance_rules": {
    "forbidden_keywords": ["최고", "확정", "즉시", "무조건"],
    "mandatory_phrase": "금융당국 심사 기준에 따라 결과가 달라질 수 있습니다.",
    "risk_alert": "수익률 언급 시 원금 손실 가능성 고지 필수"
  }
}
```

## 입력 방법 3: 자연어 기반 교정 요구사항 (추가 기능)

```text
다음 시나리오들을 에이전트 로직에 추가해주세요:

1. "60대 시니어 고객을 위한 입출금 알림 문구 모드 추가"
   → 쉬운 단어 사용 비중 대폭 상향 및 폰트 크기 안내 포함

2. "대출 마케팅 푸시 문구 작성 시 컴플라이언스 체크 강화"
   → '금리' 언급 시 최저/최고 범위를 반드시 병기하도록 Auditor 로직 수정

3. "에러 메시지 발생 시 단순 공지가 아닌 해결 방법(Action) 제시"
   → Stylist 에이전트가 해결책 노드를 찾아서 문장에 포함하도록 연결
```

---

## 입력 방법 4: 표 형식의 데이터 (테스트 셋)

| 분류 | 원문 (Original) | 타겟 고객 | 적용 컴포넌트 |
| :--- | :--- | :--- | :--- |
| **알림** | 귀하의 적금 만기가 도래하여 자동 해지 예정입니다. | 일반 | 푸시 알림 |
| **안내** | 본 상품은 원금 손실의 위험이 있으며 즉시 수익을 보장합니다. | 투자자 | 상품 상세 설명 |
| **오류** | 시스템 장애로 인해 서비스 이용이 불가합니다. | 전체 | 모달 팝업 |
| **가입** | 신분증을 지참하여 내점하신 후 신청하십시오. | 시니어 | 문자 메시지 |

## 예상 출력 (Agent가 생성해야 할 결과)

### 1. 최종 최적화 문구
> **"통장을 만든 지 벌써 1년이 되었네요! 내일이면 만기가 되어 자동으로 돈이 입금될 예정이에요. 궁금한 점이 있다면 언제든 물어봐주세요."**

### 2. 단계별 교정 로그 (Reasoning Log)
- **[Glossary]**: '만기 도래' → '1년이 되었네요', '해지' → '입금될 예정'으로 순화.
- **[Stylist]**: 격식체에서 다정한 해요체로 변경. '든든한 동반자' 페르소나 적용.
- **[Auditor]**: 금지어 없음. 필수 고지 사항 확인 완료.

### 3. 시각화 (Trace)
Mermaid를 활용한 에이전트 간 워크플로우 다이어그램 출력.

## 사용 방법 및 검증 포인트

### 사용 방법:
1. **기본 테스트**: 입력 방법 4의 표 데이터를 하나씩 입력하여 에이전트 체인 실행.
2. **파일 처리**: Word/PDF 가이드라인 업로드 시 `Compliance_rules` 노드에 실시간 업데이트 처리.
3. **결과 비교**: 원문(Raw) vs 최종본(Optimized)을 양옆에 배치(Side-by-side)하여 시각화.

### 검증 포인트 (PM 체크리스트):
- ✅ **Persona Consistency**: 전 구간에서 브랜드의 말투가 일관되게 유지되는가?
- ✅ **Compliance Filter**: '최고', '즉시' 등 위험 단어가 100% 차단되는가?
- ✅ **Reasoning Transparency**: AI가 왜 이렇게 고쳤는지 사용자가 납득할 수 있는 근거를 제시하는가?
- ✅ **File Parsing**: 업로드된 문서에서 새로운 용어/규칙을 정확히 추출하는가?
